# Architecture

1. Determine project mode and map the current boundaries, dependencies, data flow, and extension points.
2. Find existing patterns before introducing a new one.
3. State constraints, alternatives, trade-offs, and rejected options.
4. Prefer the smallest design that preserves testability, operability, and future change.
5. Consider security, privacy, accessibility, reliability, performance, operability, and cost as architecture concerns.
6. Record decisions that affect public interfaces, persistence, deployment, security, or ownership.

Do not create abstractions only to avoid a small amount of repetition.
