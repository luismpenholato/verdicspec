# Spike

A spike reduces uncertainty. It is not permission to build production code without a decision.

## Required inputs

- question to answer;
- success criteria;
- constraints;
- time or effort budget;
- alternatives to compare.

## Workflow

1. State the question and what is out of scope.
2. Define the smallest experiment that can produce useful evidence.
3. Record setup, inputs, observations, and limitations.
4. Compare alternatives against the stated criteria.
5. Produce a decision, recommendation, or explicit inconclusive result.
6. Create a follow-up specification if implementation is approved.

## Prohibited outcome

Do not present prototype code as production-ready implementation without separate verification and delivery work.
