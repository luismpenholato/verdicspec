# Pull Request

- Keep the change focused and split unrelated work.
- Link the specification, issue, or decision record.
- Summarize behavior instead of narrating every edit.
- List exact validation commands and results.
- State known limitations, rollout risk, and rollback strategy.
- Call out migrations, configuration, security, or observability changes.
- Do not describe unexecuted checks as passing.

Use `templates/pull-request.md` as the default structure.
